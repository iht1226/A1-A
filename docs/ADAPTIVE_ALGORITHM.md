# 0.2.0 적응형 스마트 기상 설계와 검증 범위

목표는 설정된 범위 안에서 기상 후보를 보수적으로 찾는 것입니다. 깊은 수면·REM·얕은 수면을 실시간 분류하거나, 실제로 가장 개운하게 깨어나는 순간을 검증했다고 주장하지 않습니다. 이 버전은 독립 설계한 통계·규칙 기반 가설이며 효과를 평가할 수 있는 기록 기능을 제공합니다.

## 참고한 공개 자료

- [Sleep as Android 공개 스마트 기상 설명](https://www.sleep.urbandroid.org/docs/sleep/smart_wake_up.html): 움직임에 기반한 제한된 기상 범위와 감도 설정이라는 공개 원리만 참고했습니다. 해당 제품이 설명하는 수면 단계 분류나 비공개 알고리즘·성능 주장을 가져오지 않았습니다.
- [Sleep as Android 자동 추적 설명](https://sleep.urbandroid.org/docs/sleep/automatic_sleep_tracking.html): 판단 전 추적을 시작하는 개념을 참고했습니다. 그 제품의 추적 시작 시각과 아래의 자체 기본 시각은 다릅니다.
- [Hilditch & McHill, Sleep inertia: current insights (2019)](https://pubmed.ncbi.nlm.nih.gov/31692489/): 기상 후 기능 저하에는 이전 수면 부족과 시각 등 여러 요인이 관여합니다. 움직임만으로 기상 효과를 확정할 수 없다는 설계 한계로 반영했습니다.
- [AASM actigraphy 임상 가이드라인 (2018)](https://jcsm.aasm.org/doi/pdf/10.5664/jcsm.7230): 움직임 관측을 통한 수면 관련 추정의 적용 범위와 한계를 참고했습니다. 이 앱에 임상적 수면 단계 판별 능력이 있다는 근거로 사용하지 않습니다.
- [Wear OS Health Services 수동 관측](https://developer.android.com/health-and-fitness/health-services/monitor-background), [공식 FGS health 유형](https://developer.android.com/develop/background-work/services/fgs/service-types#health): 배치·불규칙 수신, 서비스 권한, 저전력 API 선택에 반영했습니다.

자료는 설계의 배경입니다. 아래 숫자나 선택 규칙이 논문으로 입증되었다는 의미가 아닙니다. 비공개 구현을 복제하지 않았고 원문 코드나 알고리즘을 가져오지 않았습니다.

## 1. 시간 정책

- 기본 스마트 범위 30분, 예열 15분: 최종 시각 45분 전 측정 시작, 30분 전 판단 시작.
- 사용자 범위 10~60분: 예열은 `windowMinutes/2`를 6~15분으로 제한합니다. 10분 범위는 16분 전, 60분 범위는 75분 전부터 측정합니다.
- 분석은 30초마다 수행합니다. 가속도 요청은 약 5Hz/10초 배치이며 요청한 주기로 수신된다고 가정하지 않습니다.
- 스마트 범위에서 최근 1분 구간 세 개를 확인합니다. 후보는 추가로 60초 연속 확인해야 합니다. 분석이 45초 이상 끊기면 연속 확인을 초기화합니다.
- 예열·품질이 부족하면 기다립니다. 최종 시각은 분석의 결과나 실행 여부와 무관하게 `setAlarmClock`에 남습니다.

## 2. 개인 움직임 기준선과 특징

Android 없는 `core:analysis`의 `AdaptiveWakeEstimator`가 구현합니다. 기존 `ConservativeWakeEstimator`는 0.1.1 비교용으로 유지합니다.

1. 해당 밤 스마트 범위 이전의 관측에서 실제 측정 시간 5분 이상과 80% 이상 관측률을 요구합니다. 5초 bin의 누락은 무움직임으로 보간하지 않습니다.
2. 현재 개인의 움직임 중앙값/MAD와 지난 유효한 최대 7개 이력의 기준선 요약으로 활동 기준을 만듭니다. 첫 사용도 해당 밤의 기준선을 사용하므로 과거 기록이 필수는 아닙니다.
3. 최근 세 구간의 강도(P90), 실제 관측 시간 대비 움직임 빈도, 연속 움직임 지속시간, 변화 유지 추세를 구합니다.
4. 세 구간 중 가장 약한 근거를 택합니다. 한 번의 뒤척임·충격이 다른 조용한 구간을 높은 평균으로 덮지 못합니다. 큰 충격, 비정상 수치, 관측 공백은 보류합니다.
5. 강한 움직임 근거는 심박 없이 통과할 수 있습니다. 약한 강도만 있고 반복성·지속·추세가 충분한 경우에는 신뢰할 수 있는 심박 추세가 이를 보완할 수 있습니다. 심박만으로 통과하거나 부족한 움직임 기간을 대체하지 않습니다.

수집 품질은 센서가 실제로 제공한 범위·최신성·기기 품질을 뜻합니다. 수면 상태가 정확하다는 신뢰도가 아닙니다. 움직임이 증가했다는 사실을 ‘얕은 수면’으로 명명하지 않습니다.

## 3. 심박 보조와 센서 결합

- Health Services의 실제 측정 시각, 수신 시각, 품질을 별도로 저장합니다. HIGH/MEDIUM/LOW/미확인을 각각 내부 품질로 보존합니다.
- 지원되는 심박이 충분히 신선하고 여러 시각에 분산되어 있을 때만, 본인의 예열 중앙값/MAD 대비 변화가 보조 근거가 됩니다. 고정된 4bpm 상승은 새 알고리즘의 필수 조건이 아닙니다.
- 지연·누락·낮은 품질·권한 철회 시에는 심박 보조를 끕니다. 움직임의 강한 근거가 여전히 필요합니다.
- 센서 가중치를 고정 비율로 더하지 않습니다. 움직임의 반복·지속·추세·품질 중 최솟값을 필수 경로로 두고, 강도 경로에 한해 신뢰 가능한 심박 보조와의 최댓값을 사용합니다. 즉 품질 관문과 논리적 보완이며 ‘센서가 많을수록 정확’이라는 가정이 아닙니다.

## 4. 수면 손실 비용과 보수성

판단 기준은 기본 기준 + 남은 시간에 따른 수면 손실 비용 + 기상 시각 접근에 따른 보수 항 + 최근 짧은 수면 참고 항 + 개인화 조정입니다.

보수 항은 감소하는 수면 손실 비용보다 적어도 빠르게 증가하도록 파라미터를 검증합니다. 같은 관측 근거에서 시간이 흘렀다는 이유로 통과하기 쉬워지지 않습니다. 이것은 실제 기상 이득을 측정한 효용 함수가 아니라, 손실을 드러내고 검증하기 위한 보수적 대리 정책입니다.

`AdaptiveParameters`에 모든 수치·품질·구간·비용 기준을 분리했습니다. 사용자는 화면의 ‘보수 기준’으로 기본 기준을 조절합니다. 현재 값은 Watch7 실측으로 피팅되지 않은 초기 공학 가설입니다. 내부 근거 지수는 성공 확률이나 의료 수치가 아닙니다. 이력에 버전, 파라미터 문자열, 사용자 기준, 개인 기준선 배열·조정·수면 맥락 스냅샷을 보관합니다.

## 5. 개인화와 삼성 헬스

- 움직임/심박 원본은 워치 자체 관측입니다. 심박의 현재 밤 기준선은 개인별로 계산합니다.
- 과거 유효한 움직임 기준선과 현재 기준선을 함께 사용합니다. 적응형으로 실제 예약한 일반 스마트 이력 중 양질 관측과 기상 평가가 8회 이상이면 개운함·졸림 차이의 평균으로 기준을 최대 ±0.04만 조정합니다. 시험 버튼·일반 알람·미래 평가·낮은 품질은 학습에서 제외합니다.
- 기록이 적으면 평가 기반 조정은 0입니다. ML 모델을 도입하지 않았습니다.
- 휴대전화에서 기존 READ_SLEEP 권한으로 최근 삼성 수면 기록을 읽습니다. 알려진 단계가 세션의 90% 미만이면 총 수면 시간을 만들어내지 않습니다. 겹치는 단계도 합산하지 않습니다.
- 사용자가 ‘수면 요약을 워치 개인화에 사용’을 선택하면 충분한 단계가 있는 최근 날짜별 대표 세션의 평균 길이·기록 수·기록 시각을 전송합니다. 이 요약은 짧은 수면 시 더 보수적인 비용에만 쓰며, 수면 단계 정답이나 실시간 입력이 아닙니다. 워치의 정시 알람은 휴대전화 연결을 필요로 하지 않습니다.
- 과거 7일 전체 통계라도 마지막 수면이 오래되면 맥락을 무시합니다. 계획이 만들어진 뒤의 평가나 건강 기록을 해당 계획의 과거 판단에 소급 적용하지 않습니다.
- Health Connect 심박 읽기 권한은 추가하지 않았습니다. 삼성 실시간 단계, EEG, 원시 PPG, 정밀 HRV를 수집한다고 가정하지 않습니다.

## 6. 조기·최종 알람 상태

| 동작 | 결과 |
|---|---|
| 조기 알람 무응답 | 최종 예약 유지 |
| 조기 알람 명시적 해제, 기본 옵션 | 최종 포함 전체 취소 |
| 조기 해제 후 정시 백업 유지 옵션 ON | 현재 울림만 해제, 최종 예약 유지, 조기 재실행 없음 |
| 조기 다시 알림 | 요청 시각과 최종 시각 중 이른 쪽. 최종 시각이면 중복 재알림을 만들지 않음 |
| 최종 알람 후 다시 알림 | 기존처럼 설정된 간격으로 예약 가능 |
| 최종 알람 명시적 해제 | 백업 옵션과 무관하게 종료 |
| 워치 ‘예약 해제’ | 백업 옵션과 무관하게 전체 취소 |
| 후보 없음·분석 실패·휴대전화 단절 | 최종 시각 일반 알람 유지 |

현재 울림 nonce로 오래된 해제·다시 알림 동작을 거부합니다. 재부팅 복원은 계획에 저장한 선택 알고리즘과 최종 시각을 유지합니다.

## 7. 동일 관측 비교와 실제 경험 비교

### 동일 관측

`CausalComparison`이 각 실제 분석 시각에 두 알고리즘을 병렬 적용합니다. 원본 0.1.1 함수와 동일한 60초 확인 관문을 사용합니다. 늦게 도착한 심박을 과거 평가에 넣지 않도록 측정 시각과 수신 시각을 모두 검사합니다. 첫 제안 시각과 그때의 근거를 고정해 보관하고, 제안이 없으면 마지막 보류 이유를 기록합니다.

실제 알람 요청 시점부터 관측을 중단합니다. 다른 알고리즘이 그 이후 언제 울렸을지는 알 수 없으므로 ‘관측 내 없음 / 종료 이후 비교 불가’로 표시합니다. 0.1.1 DB에는 수신 시각이 없으므로 마이그레이션 시 도착 시각을 임의로 생성하지 않으며 신규 인과 비교에서 제외합니다.

이 비교는 의사결정 차이만 보여 줍니다. 한 쪽이 빨리 선택했다는 사실은 실제 기상 효과의 우열을 뜻하지 않습니다.

### 여러 날의 실제 경험

사용자가 ‘매일 번갈아’ 또는 ‘날짜별 무작위’ 모드를 선택해야 시험 배정을 합니다. 기본은 적응형 단독입니다. 같은 모드·같은 기상 날짜의 재예약과 재부팅은 배정을 유지합니다. 선택 알고리즘은 계획과 이력에 저장합니다.

각 이력에는 알고리즘/시험 모드, 요청 시각, 출력 API 시작 시각(확인 가능할 때), 최초 해제 시각, 조기 여부, 삼성 참고 수면 합계(제공 시), 개운함·졸림(각 1~5), 센서 구간 배터리 시작·종료를 기록합니다. 알람이 실제 사용자를 깨웠거나 스피커에서 소리가 났다는 하드웨어 확인은 할 수 없습니다. ‘출력 API 시작’과 ‘실제 각성’은 다릅니다.

배터리는 제한된 센서 수집 구간의 %p 차이이며 밤 전체 소비가 아닙니다. 충전·미지원·미완료는 소비량으로 합산하지 않습니다. 삼성 기록 연결은 종료 시각이 가까운 참고 후보이며, 완전한 세션 매칭·PSG 정답이 아닙니다.

휴대전화는 선택한 시험 이력의 알고리즘별 건수·평가 평균·제공된 수면 합계 평균을 보여 줍니다. 일별 수면 조건·기대 효과·자기 보고·표본 수 차이를 보정한 임상 시험이 아닙니다.

## 8. Wear OS와 배터리

- 가속도 5Hz 요청/10초 배치와 30초 분석을 분리합니다. wake-up 센서를 우선하고 없으면 일반 센서를 사용하되 공백을 낮은 품질로 처리합니다. 밤새 CPU wake lock을 잡지 않습니다.
- 심박은 PassiveMonitoringClient를 제한된 수집 구간에서만 사용합니다. 운동을 가장한 ExerciseClient나 고주파 심박 측정은 하지 않습니다.
- 심박 없이 health FGS를 쓰는 경우 공식 선행 권한인 ACTIVITY_RECOGNITION을 별도로 요청합니다. 사용자가 이 권한을 거부했고 백그라운드 심박 권한도 없으면 스마트 분석을 시작하지 않습니다. 제한된 BODY_SENSORS_BACKGROUND를 우회하지 않습니다.
- 심박은 선택 사항입니다. 심박 권한을 잃어도 허용된 움직임 분석은 계속할 수 있으며 기존 심박 캐시로 보조 판단을 계속하지 않습니다.
- 센서 원본은 48시간 후 다음 수집 때 정리하고 요약은 최대 60회 보관합니다. 실제 밤별 비교를 장기간 하려면 삭제 전에 보관 범위를 고려해야 합니다.
- Doze, 절전, 프로세스 종료, 재부팅에서 센서 공백은 허용하며 최종 예약과 분리합니다. 강제 중지, 권한 철회, 전원 꺼짐·방전, OEM 정책, DND·음량 제한까지 실행을 보장하지 않습니다.
