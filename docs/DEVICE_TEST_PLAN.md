# 0.4.0 추가 실기기 시험 — 모두 미실행

[SENSOR_RELIABILITY.md](SENSOR_RELIABILITY.md)의 화면 켬/꺼짐 10·15분 시험과 다음 실제 밤 절차를 먼저 수행하세요. wake-up 유무, FIFO, 이벤트/저장 관측률, 시각·공백·폐기 사유·DB 지연을 내보내고 95구간 기록과 비교합니다. non-wake-up에서는 연속 수집을 보장하지 않습니다. 정상 정시 소리/진동과 재부팅/절전/연결 단절도 실제 기기에서 다시 확인해야 합니다.

아래는 기존 기능의 실기기 계획입니다.

# 실제 기기 검증 계획

**아래는 미실행 절차입니다. 실행 완료 기록이 아닙니다.** 실제 Watch7과 페어링된 Android 휴대전화가 필요합니다. OS/One UI Watch/삼성 헬스 버전, 앱 커밋·APK SHA-256, 배터리·알람 음량·권한·DND 상태를 시험마다 기록하세요. 처음에는 낮에 짧은 알람으로 검증하고 별도 신뢰 가능한 알람을 함께 준비하세요.

## 진단 명령

`WATCH_SERIAL`을 `adb devices`에 표시되는 값으로 바꿉니다. 시험 후 idle/배터리 시뮬레이션은 원상 복구하세요.

```bash
adb -s WATCH_SERIAL shell dumpsys alarm
adb -s WATCH_SERIAL shell dumpsys package dev.sleepalarm.app
adb -s WATCH_SERIAL logcat -v time

# 화면 끄기 및 Doze 시험
adb -s WATCH_SERIAL shell input keyevent 223
adb -s WATCH_SERIAL shell dumpsys battery unplug
adb -s WATCH_SERIAL shell dumpsys deviceidle force-idle
# 시험 후 복구
adb -s WATCH_SERIAL shell dumpsys deviceidle unforce
adb -s WATCH_SERIAL shell dumpsys battery reset

# 일반 프로세스 종료와 강제 중지는 다른 시험
adb -s WATCH_SERIAL shell am kill dev.sleepalarm.app
adb -s WATCH_SERIAL shell am force-stop dev.sleepalarm.app
# 강제 중지 후에는 런처에서 앱을 다시 열고 복원을 확인

adb -s WATCH_SERIAL reboot
```

일부 OEM 빌드에서는 명령이 제한되거나 메뉴가 달라집니다. 시스템 권한을 강제로 부여해 통과시킨 시험은 일반 설치 경로 검증으로 기록하지 마세요. 제한된 BODY_SENSORS_BACKGROUND 권한의 정상 설치·허용 흐름 자체도 확인 대상입니다.

## 장기간 판단 검증

기상 용이성은 이 코드의 단위 테스트로 검증할 수 없습니다. 적어도 여러 밤의 착용 데이터와 주관적인 기상 만족도, 오탐, 누락, 배터리 사용을 함께 확인해야 합니다. 삼성 헬스의 사후 단계와 비교하는 것만으로 기상 알고리즘의 효과가 입증되지는 않습니다. 실시간 센서 자료를 수면 단계의 정답으로 표시하지 마세요.
