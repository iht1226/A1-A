- API 33+ 알람 시계 용도의 USE_EXACT_ALARM, API 31/32의 SCHEDULE_EXACT_ALARM을 분리합니다. 알림 미허용만으로 워치·휴대전화 명령의 알람 예약을 차단하지 않습니다.
- 정확한 알람 API/설치 권한/알림/채널/전체 화면 상태를 별도 표시하고, 미지원 설정 화면을 안전하게 대체합니다.
- core:update 모듈: 공개 GitHub Release 감지, 선택적 Wi-Fi 주기 다운로드, 크기·SHA-256·서명·버전·기기 종류 검증, Data Layer 워치 전송, PackageInstaller 사용자 승인, 제한 구간 설치 차단.
- 워치 외부 설치 UI 미지원과 이전 임시 키의 서명 전환 한계를 명시합니다. 기존 앱 자동 삭제/무승인 설치는 없습니다.
- Secrets 기반 양쪽 release 서명과 APK/update.json 공개 배포를 추가합니다. Secrets가 없으면 서명 배포를 생략하며 임시 debug 키로 대체하지 않습니다.
- 로컬 299개 테스트와 debug 빌드/lint 통과. 실제 기기 권한·설치·기상 효과는 미검증입니다.

# 0.2.0 — 적응형 스마트 기상과 관측 가능한 비교

- 기존 독립 AlarmManager 정시 예약과 모듈 구조를 유지합니다. 양쪽 앱 versionCode 3, applicationId와 기본 debug 서명 설정은 유지합니다.
- 움직임의 개인 기준선·강도·빈도·지속·추세·관측 품질을 사용합니다. 심박은 선택적 보조 근거이며 심박 상승을 필수 조건으로 사용하지 않습니다. 고정 센서 가중치나 수면 단계 분류를 사용하지 않습니다.
- 기본 측정은 최종 시각 45분 전, 판단은 30분 전부터입니다. 10~60분 범위에 맞춰 사전 예열을 조정하며 모든 51개 범위에서 판단 기회를 시험했습니다.
- 정시 예약은 조기 울림만으로 취소하지 않습니다. 명시적 해제와 백업 유지 옵션을 구분하고 조기 다시 알림을 최종 시각 이내로 제한합니다. 재부팅 복원에서도 중복 예약을 방지합니다.
- 실제 수신 시각과 관측 종료를 저장합니다. 같은 관측에 대한 0.1.1/0.2.0 판단 비교, 선택적 날짜별 교대·무작위 배정, 출력 요청·해제·평가·센서 구간 배터리를 기록합니다.
- Health Connect 수면 기록은 참고 자료로 유지합니다. 완전한 기록의 수면 시간만 사용하며, 사용자가 전송한 요약과 과거 개인 센서 기준선·8회 이상 평가로 제한적 통계 조정을 합니다.
- 움직임 측정 권한과 선택적 심박 권한을 분리합니다. 저장 DB 마이그레이션 및 이전 예약 JSON을 지원합니다.
- 로컬 자동 테스트 285개 통과, 두 APK 빌드 및 lint Error 0. 실제 Watch7 기상 효과·센서·전원 정책은 미검증입니다.

설계·공개 연구 근거·한계: [ADAPTIVE_ALGORITHM.md](ADAPTIVE_ALGORITHM.md). 검증: [VALIDATION.md](VALIDATION.md).

# 0.1.1 — 스마트 범위·시험 예약·알람 실패·권한 안내 수정

기존 모듈 구조와 워치의 독립 최종 AlarmManager 예약을 유지했습니다. applicationId와 Data Layer 프로토콜은 그대로이며 양쪽 앱 versionCode는 2입니다.

1. **모든 스마트 범위의 판단 기회**
   - 10~14분: 기준 4분 + 최근 2분 관측 + 연속 60초 확인.
   - 15~60분: 기준 6분 + 최근 3분 관측 + 연속 60초 확인.
   - `WakeTiming`과 `SustainedWakeGate`를 분석 모듈에 두고 실제 센서 서비스가 같은 값을 사용합니다.
   - 30초 평가, 최대 15초 등록 대기, 5초 bin 위상 차이를 반영해 10~60분 **모든 51개 범위**를 검사합니다. 짧은 범위도 최종 시각 전에 판단 기회가 남습니다. 이는 실제로 잠이 얕아지는 시점이 존재하거나 스마트 기상이 반드시 발생한다는 뜻이 아닙니다.
   - 데이터 품질·누락·최신성·심박 분산·두 센서 공동 근거 조건은 유지합니다. 평가가 45초 넘게 끊기면 60초 확인을 다시 시작합니다.
2. **시험 예약과 사용자 설정 분리**
   - 워치 버튼은 `AlarmController.armTest`를 사용합니다. 시험 계획 스냅샷에만 `smartEnabled=false`를 적용하고 사용자 설정 저장을 호출하지 않습니다.
   - 저장 설정은 앱 재실행·시험 복원·해제 후에도 보존됩니다. 정상 예약 경로의 설정 저장은 유지합니다.
   - 시험 버튼은 기존 활성 예약을 교체합니다. 여러 알람을 동시에 예약하는 기능은 추가하지 않았습니다.
3. **Foreground Service 실패 처리**
   - Controller의 서비스 시작 예외·null 반환과 서비스 내부 알림 생성/전경 승격 예외를 따로 처리합니다.
   - 전경 승격 실패 시 자원을 정리하고 서비스를 중지하며 `START_NOT_STICKY`를 반환합니다. 일반적인 정상 울림은 기존 `START_STICKY`입니다.
   - 별도 알림 채널·ID에 시스템 알람 소리/진동을 요청하고 직접 1회 진동도 별도로 시도합니다. 알림이 차단되어도 직접 진동을 시도하며, 둘 다 실패하면 그 제한을 오류에 포함합니다.
   - 실패한 서비스가 정리되어도 대체 알림이 남습니다. 해제·다시 알림은 대체 알림·진동도 중지합니다. 스마트 알람 서비스 실패가 원래 최종 예약을 취소하지 않습니다.
   - 오류는 `SleepAlarm` Logcat과 별도 저장 필드에 기록하고 워치에 ‘최근 알람 오류’로 표시합니다. 센서 콜백이 오류를 덮어쓰지 않습니다.
   - 알림 권한/채널/DND/기기 정책/진동 하드웨어 제한 때문에 대체 전달도 보장할 수 없습니다. 요청 성공과 실제 출력 성공을 구분합니다.
4. **백그라운드 센서 권한 안내**
   - 선행 심박 권한 없음, 미허용, 요청 후 거부 또는 설정 미완료, 확인된 설치자 제한을 구분합니다.
   - 공개 API에서 설치 허용 목록을 조회할 수 없으면 ‘확인할 수 없음’으로 표시합니다. 사용자 거부·설정 취소·관리 정책 중 무엇인지 OS가 공개하지 않으면 원인을 단정하지 않습니다.
   - ‘앱 시스템 설정 → 권한 → 신체 센서 → 항상 허용’을 안내하고, 항목 부재·비활성화 시 설치 경로/기기 관리 정책을 확인하도록 합니다.
   - 심박 권한보다 백그라운드 권한을 먼저 요청하거나, 확인된 설치자 제한 상태에서 불가능한 요청을 반복하지 않습니다. 일반 알람은 유지합니다.
